# Подробный справочник RedflagAutoMute 2.0.0

[← Установка и краткое руководство](../README.md)

Отдельное приглашение к базе: Подключение → Поделиться подключением. Код rfdb1 содержит только публичные настройки проекта; после входа он не присоединяет к чужим группам. Приглашение rfam1 настраивает базу и присоединяет к конкретной группе.

Совместные **локальные голосовые мьюты** в Discord. Плагин BetterDiscord устанавливается одним файлом; сервер поднимать не нужно. Firebase Realtime Database и Authentication обслуживают все независимые группы в одном облачном проекте.

## Что изменилось

- Вместо перезаписываемого общего статуса — одна карточка от каждого участника на каждого Discord-пользователя.
- Любая красная или две жёлтые **от разных участников** дают локальный мут. Одна жёлтая — предупреждение; можно включить мут и за неё.
- Можно подключить несколько групп и отключать каждую отдельно. Мут применяется, если его требует хотя бы одна активная группа.
- Две жёлтые считаются внутри одной группы: по одной жёлтой в двух разных группах не складываются. Группы, к которым вы не присоединились, и отключённые группы не учитываются.
- Вместе со звуком по умолчанию локально отключается видео пользователя. При снятии мута восстанавливается предыдущее состояние; уже отключённое вручную видео плагин не включает.
- Аватарки и карточки пользователей, заблокированных активной базой, получают красную рамку. Личное разрешение снимает звук/видео-мут, но оставляет информацию о статусе в базе.
- В личную заметку Discord добавляются статус, ID записи (`ID группы / Discord ID`) и время блокировки в UTC; для одной жёлтой — предупреждение. Время определяется текущими действующими голосами: первая красная либо вторая жёлтая. Это не неизменяемая история банов. Существующий текст сохраняется. Если места в заметке недостаточно, запись пропускается. При отзыве карточки или отключении группы убирается только отметка плагина. Пока плагин полностью выключен, заметка хранит последний известный статус. Обновление заметок и отключение видео можно выключить в настройках.
- В меню красная и жёлтая карточки обозначены цветными флажками.
- Личное «всегда разрешать» перекрывает все группы. Есть и личный принудительный мут.
- Участник меняет/отзывает только собственную карточку. Владелец исключает участников; их голоса перестают учитываться. При исключении автоматически меняется приглашение.
- Плагин отслеживает свои мьюты и снимает их при отзыве карточек, отключении группы или плагина. Уже существовавшие ручные мьюты и индивидуальная громкость не меняются.
- Голосовой мут и отключение видео применяются только к участникам вашего текущего звонка. Изменения состава звонка, переключение канала и сброс мьюта отслеживаются событиями Discord; резервная проверка выполняется каждую секунду. После выхода участника снимается только мут, поставленный плагином. Рамки и заметки по базе продолжают работать вне звонка.
- Событийная синхронизация Firebase (SSE): подписка на личный список групп и каждую группу, начальный снимок и последующие изменения. В исправном режиме периодических чтений нет. При сбое — резервный опрос через 5 секунд (после ошибки HTTP через 30 секунд), переподключение с задержкой 1–30 секунд. После восстановления приходит свежий снимок; токен обновляется при необходимости, соединение планово пересоздаётся через 45 минут. При 90 секундах без данных или keep-alive соединение пересоздаётся. Входящего участника проверяем сразу по последней локальной копии, без ожидания сети; при отказе в доступе копия группы удаляется.
- Приглашение содержит настройки Firebase и случайный секрет группы. Другу не нужно создавать Firebase-проект.

Это **не** серверный мут, бан, блокировка аккаунта или скрытие текстовых сообщений. Данные карточек доступны участникам конкретной группы, не всем пользователям плагина.

## Установка

1. Установите [BetterDiscord](https://betterdiscord.app/). Переход с Vencord требует замены клиентской модификации; не внедряйте оба мода в один Discord.
2. Откройте Discord → Settings → BetterDiscord → Plugins → Open Plugins Folder.
3. Скопируйте `dist/RedflagAutoMute.plugin.js` в эту папку и включите плагин.
4. Откройте его настройки. Публичная сборка не содержит ключей или адреса чьего-либо Firebase-проекта. Владелец указывает конфигурацию своей базы в настройках. Друг выбирает «Подключение → У меня есть приглашение», вставляет код и нажимает «Продолжить».
5. Зарегистрируйте отдельную учётную запись Firebase (email/пароль) либо войдите в существующую. Пароль Discord не нужен. Пароль не сохраняется; токен сессии сохраняется локально в BetterDiscord.
6. В разделе «Мои группы» создайте группу или выберите «По приглашению». Если код введён до входа, присоединение произойдёт автоматически. В приглашении нет пароля/токена вашей учётной записи.
7. ПКМ по пользователю → Redflag → группа → карточка. Если меню изменилось после обновления Discord, карточку можно выдать по Discord ID в настройках плагина.

На другом компьютере подключите ту же базу и войдите в тот же аккаунт плагина: все ваши группы загрузятся автоматически. Приглашение нужно только для первого вступления. Список членства хранится в приватном `userGroups/<Firebase UID>`; создание, вступление, выход и удаление обновляют его атомарно. Старые локальные группы автоматически индексируются при первом запуске обновления. Включение/отключение группы остаётся личной настройкой устройства.

## Firebase: один раз для всей компании

`firebase.public.json` — пустой шаблон. Сборка откажется работать, если вписать в него конфигурацию проекта. Настройки вводятся в BetterDiscord и хранятся отдельно от файла плагина. Для локальных облачных тестов используется игнорируемый Git файл `firebase.local.json`.

1. В [Firebase Console](https://console.firebase.google.com/) создайте проект. Analytics и Gemini не нужны.
2. Authentication → Sign-in method → Email/Password → Enable. Email link не нужен.
3. Realtime Database → Create Database → выберите регион → **Locked mode**.
4. Realtime Database → Rules: замените правила содержимым `firebase/database.rules.json`, затем Publish. Не включайте публичные `.read: true` / `.write: true`.
5. Project settings → General → Web API key. Если ключ ещё не создан, зарегистрируйте Web app (Hosting не нужен).
6. Скопируйте Web API key и корневой URL Realtime Database в настройки плагина.

API key — публичный идентификатор проекта, **не пароль базы**. Доступ проверяется по Firebase ID token и членству в группе. Запросы плагина выполняются через нативный `BdApi.Net.fetch`, вне браузерного CORS/CSP; облачный тестовый скрипт использует Node HTTPS. Серверный SDK, service account, Cloud Functions и собственный сервер не нужны.

## Интерфейс и группы

«Мои группы» автоматически показывает группы аккаунта из подключённой базы. Откройте группу, чтобы включить/отключить её, увидеть записи и участников, получить приглашение или выйти. Владелец может удалить группу для всех участников. Перед удалением открывается подтверждение «Удалить навсегда» / «Отмена»; будут удалены карточки, приглашение и записи в списках участников. Отключение группы остаётся обратимой альтернативой только для своего устройства. Каталога чужих закрытых групп нет. Регистрация создаёт аккаунт пользователя в настроенном Firebase-проекте, а не новый проект/базу. Технические настройки находятся в «Подключении», индивидуальные — в «Моих настройках», объяснения и диагностика — в «Как это работает». Кнопки используют BdApi.Components, цвета и шрифт наследуются от темы Discord.

## Группы и доступ

- Плагин не запрашивает Discord token. Firebase-личность независима от Discord; используйте отдельный Firebase-аккаунт на человека.
- Любой участник может передать приглашение дальше. Выбирайте участников, которым доверяете. При исключении владельцем старое приглашение сразу перестаёт работать для новых подключений.
- Удалённый участник не читает группу и не пишет карточки. Его старые карточки хранятся, но не учитываются; при повторном вступлении они снова учитываются.
- Владелец неизменяем. Только он может удалить группу; передача владения пока не поддерживается.
- Личные исключения и владение локальными мьютами разделены по Discord-аккаунтам. Не публикуйте файл настроек BetterDiscord: он содержит токены входа, приглашения и кэш.
- Firebase имеет квоты. Плагин рассчитан на небольшие компании; при подключении читается снимок группы, затем приходят изменения; повторное чтение используется при восстановлении соединения и резервном опросе. Платный тариф код не включает.
- Если человек был замьючен плагином, последующий ручной мут нельзя отличить от мута плагина. Используйте «Всегда мутить лично мне» для устойчивого личного решения.

## Лимиты и перенос мьютов

На аккаунт Firebase допускается до **5 собственных групп**. На группу — до **5000 записей пользователей**, включая жёлтые карточки и записи с голосами бывших участников. Повторный голос за того же пользователя не занимает новое место. Отзыв последнего сохранённого голоса освобождает место; удаление группы освобождает место владельца. Лимит относится к аккаунту, а не физическому человеку: создание другого аккаунта не предотвращается этими правилами.

Ограничения обеспечивают Realtime Database Rules: пять фиксированных ownerSlots и 5000 связанных slots/targetSlots. Удаление/подмена занятого места без удаления соответствующей записи запрещены. Клиент отправляет изменения атомарно и повторяет запрос при конфликте. Не заменяйте эти правила публичной записью. После обновления правил используйте обновлённую сборку на всех клиентах.

В группе откройте **Импорт / экспорт**:

1. **Выгрузить мои мьюты Discord** читает сохранённые локальные голосовые мьюты MediaEngineStore, независимо от состава текущей комнаты. Список общий для всех серверов текущего клиента: обход серверов не нужен. Переключатели позволяют дополнительно включить пользователей с громкостью 0% и заблокированные аккаунты. Категории показываются отдельно, пересечения удаляются. Мьют только трансляции не включается. История, отсутствующая в текущем клиенте, не восстанавливается; со старого устройства можно экспортировать отдельный файл и объединить при импорте.
2. **Выгрузить баны группы** экспортирует красные карточки и пользователей с двумя жёлтыми.
3. **Сохранить JSON-файл** открывает штатный диалог. В файле только Discord ID и метаданные экспорта, без настроек базы, приглашений и токенов. Передавайте файл тем, кому доверяете.
4. Для импорта выберите JSON/TXT (до 2 МБ) либо вставьте список ID по одному на строку. Нажмите **Проверить список**, затем **Подтвердить импорт красных флажков**. Числовые JSON-значения отвергаются: ID должны быть строками, иначе теряется точность.
5. Импорт выдаёт ваши красные карточки в выбранной группе. Чужие голоса сохраняются, дубликаты убираются, собственный Discord ID исключается. Существующие ваши красные не получают новую дату. Для новых карточек дата блокировки — время импорта, не историческая дата мута в Discord. Весь пакет записывается атомарно: при ошибке частичного импорта нет.

Друзья выполняют экспорт в своих Discord-клиентах и передают JSON для импорта в общую группу. Личные списки не отправляются в облако до подтверждения импорта.

Импорт автоматически объединяет списки по Discord ID. Если вы импортировали A и B, а друг — B и C, в группе будет три записи: A, B, C. У B сохранятся карточки обоих авторов; одна запись занимает одно место из 5000. Повторный импорт тем же автором не создаёт дубликаты и не обновляет дату существующей красной карточки. Экспорт группы также содержит каждый ID один раз. Разные группы не объединяются автоматически.

В проверенной 11.10.2026 сборке Discord таблица `audioContextSettings` ограничена 300 записями отдельно для обычного звука и трансляций. Мьют, индивидуальная громкость и отключение саундборда используют общую запись пользователя. При переполнении удаляются записи с самой старой `modifiedAt`. Поэтому 254 голосовых мьюта не означают лимит 255. Это внутреннее поведение конкретной сборки, не гарантированный Discord API. Плагин хранит полный список в Firebase, а в аудионастройках поддерживает только нужные мьюты текущего звонка; утраченная до импорта история автоматически не восстанавливается.

## Разработка и проверки

Нужен Node.js 22+. Для сборки и локальных тестов не нужны внешние npm-зависимости:

```sh
npm run check
```

- `src/core.cjs`: правила карточек и владение мьютами.
- `src/transfer.cjs`: формат переноса, список Discord-мьютов, распределение мест и кодирование приглашений.
- `src/features.cjs`: локальное видео, личные заметки и рамки аватарок.
- `src/settings.cjs`: интерфейс настроек и управление группами.
- `src/firebase.cjs`: Firebase Auth REST, обновление токенов, группы, членство, карточки.
- `src/transport.cjs`: ограниченный по времени/размеру HTTPS-транспорт без редиректов.
- `src/plugin.cjs`: адаптер BetterDiscord, меню, настройки, жизненный цикл и синхронизация.
- `scripts/build.cjs`: сборка одного переносимого `.plugin.js`.
- `test/`: проверки правил, REST-запросов, гонок и жизненного цикла с подставным Discord.
- `firebase/database.rules.json`: правила доступа для облака.

Для явной проверки **своего** облачного проекта создайте `firebase.local.json` с полями `apiKey` и `databaseURL`, затем запустите `node scripts/cloud-smoke.cjs --run`. Скрипт создаёт три синтетические учётные записи и группу `QA smoke test …`, проверяет изоляцию групп и отзыв доступа, удаляет тестовые карточки. Сама QA-группа и три учётные записи остаются для повторных прогонов; их токены находятся только в игнорируемом Git файле `cloud-smoke.local.json`. В обычные тесты этот сценарий не включён.

Облачная проверка покрывает восстановление списка на чистом клиенте, приватность индекса, удаление только владельцем, очистку индексов участников, создание группы, присоединение, обмен карточками, накопление жёлтых, запрет чтения посторонним, запрет изменения чужих карточек и владельца, исключение участника и отзыв приглашения. Результаты конкретного окружения сохраняются локально и не входят в публичный архив.

### Публикация без секретов

Публикуйте только подготовленный архив исходников или один файл `dist/RedflagAutoMute.plugin.js`. Не загружайте всю рабочую папку: в ней могут находиться локальные токены, конфигурация, скриншоты Discord и старые архивы. Они исключены из публичного пакета. `.gitignore` не удаляет файлы, уже попавшие в Git, поэтому перед коммитом проверяйте staged diff. `npm run audit:release` проверяет исходники публичного пакета и сборку на известные локальные секреты и распространённые форматы ключей.

Тесты с подставным Discord **не доказывают** совместимость с текущими внутренними модулями живого клиента. При обновлении Discord может потребоваться правка только адаптера `MediaEngineStore.isLocalMute` / `toggleLocalMute` и идентификаторов меню.

### Ручная приёмка на двух клиентах

1. Две разные Firebase-учётные записи, одна группа по приглашению.
2. Участник A выдаёт красную тестовому Discord-пользователю: на обоих клиентах должен появиться локальный голосовой мут не позже следующей синхронизации.
3. A отзывает карточку: оба снимают только свои мьюты. Предварительно поставленный вручную мут остаётся.
4. По одной жёлтой от A и B: первая не мутит, вторая мутит. Отзыв одной снимает мут.
5. Личное «разрешать» на B: у A мут остаётся, у B снимается.
6. Выключение группы/плагина, перезапуск Discord, сетевой обрыв и восстановление.
7. Исключение участника: доступ и его голоса пропадают; старое приглашение не позволяет войти заново.
8. Красная карточка: рамка, личная заметка, локальное отключение видео. После отзыва рамка и отметка исчезают, предыдущее состояние видео восстанавливается. Проверьте отдельно уже отключённое вручную видео и заметку с собственным текстом.

## Старый проект

`RedflagAutoMute_old/` и `Vencord/src/userplugins/RedflagAutoMute/` сохранены как исходные версии. Изменённые ранее `Vencord/package.json` и `Vencord/pnpm-lock.yaml` не затрагивались.

В старой версии `mutedUsers` создавал новый `Set` из базы при каждом обращении, из-за чего реальные и требуемые мьюты смешивались. Начальная синхронизация пропускала старые карточки. В новой заготовке Vencord отсутствовало применение мьютов и `Promise<boolean>` проверялся как boolean. Firebase API key использовался вместо пользовательского ID token.

Попадание в основную ветку Vencord не обязательно: [custom plugins поддерживаются через локальную сборку](https://docs.vencord.dev/installing/custom-plugins/). BetterDiscord выбран ради установки [одного файла плагина](https://docs.betterdiscord.app/plugins/introduction/structure).

Справка: [Firebase Auth REST](https://firebase.google.com/docs/reference/rest/auth), [Realtime Database REST authentication](https://firebase.google.com/docs/database/rest/auth), [Database rules](https://firebase.google.com/docs/database/security/core-syntax), [BetterDiscord API](https://docs.betterdiscord.app/api/).
