# RedflagAutoMute 2.0.3

**Муть токсичных людей вместе с друзьями.**

![Как работает RedflagAutoMute](docs/images/overview.svg)

Общий список нежелательных собеседников для вашей компании в Discord. Один участник выдаёт флажок — плагин применяет правила группы у остальных. Голос и вебкамера отключаются **локально, только для вас**. Это не серверный бан и не скрытие текстовых сообщений.

**[Скачать установочный ZIP для Windows](https://github.com/HilistonGit/Vencord_RedflagAutoMute/releases/download/v2.0.3/RedflagAutoMute-2.0.3.zip)** · [Все файлы релиза](https://github.com/HilistonGit/Vencord_RedflagAutoMute/releases/tag/v2.0.3) · [Подробный справочник](docs/REFERENCE.md)

## Начать за три шага

1. **Скачайте ZIP по ссылке выше и распакуйте полностью.** Запустите `Install.cmd`. В меню выберите **1 — Установить / восстановить + включить автовосстановление**. При необходимости полностью закройте Discord, включая значок в трее. Скрипт проверит SHA-256, установит плагин и BetterDiscord через официальный CLI, затем сам проверит результат. Отдельное окно установщика BetterDiscord больше не требуется. Для обычной установки в профиль пользователя права администратора не нужны.
2. **Включите плагин:** Discord → Настройки → BetterDiscord → Плагины → RedflagAutoMute → переключатель. Откройте шестерёнку рядом.
3. **Вставьте приглашение друга:** Подключение → У меня есть приглашение → Продолжить. Появится форма «Войти в аккаунт плагина» с email и паролем. Для первого подключения нажмите «Нет аккаунта? Создать», заполните поля и нажмите «Создать аккаунт». Если аккаунт уже есть — нажмите «Войти». Используйте отдельный пароль — пароль Discord или Google не нужен.

Приглашение в группу подключает и базу, и группу. Другу **не нужно создавать Firebase-проект или поднимать сервер**. На другом устройстве войдите в тот же аккаунт плагина в той же базе: ваши группы загрузятся автоматически.

> Уже используете Vencord? Сначала замените клиентскую модификацию на BetterDiscord по его инструкции. Установщик RedflagAutoMute не удаляет Vencord и не устанавливает два мода поверх друг друга. После обновления Discord загрузчик может слететь; фоновая проверка обнаруживает это в новой версии клиента.

### Меню и автовосстановление Windows

- **1** — установка и включение фоновой проверки; **2** — установка без изменения состояния фоновой задачи.
- **3** — диагностика, время последней проверки и пути журналов; **4** — отключение фоновой проверки.
- **5** — выбор Stable, PTB или Canary. По умолчанию выбран Stable.

Автовосстановление — задача Планировщика Windows **от имени текущего пользователя**, без пароля и прав администратора. После входа в Windows и каждые 2 минуты проверяет запуск Discord. Ждёт завершения обновления клиента и даёт плагину 3 минуты на запуск. Исправно работающий сеанс не обновляет и не перезапускает. При ручной первоначальной установке не запускайте Discord до её завершения.

После слетевшего загрузчика или неудачного запуска включённого плагина задача проверяет последний стабильный релиз BetterDiscord. Если исправление ещё не вышло, повторяет поиск раз в 15 минут, не переустанавливая ту же неработающую версию. Когда доступно исправление, скачивает проверенный официальный CLI, восстанавливает BetterDiscord и ждёт сигнала успешного запуска плагина. Отсутствующий файл плагина восстанавливает из локальной копии.

Если для восстановления нужно перезапустить открытый Discord, появляется окно с отсчётом **60 секунд** и кнопками **«Восстановить сейчас» / «Отложить на час»**. Без действий восстановление начинается после отсчёта; закрытие окна откладывает его. При начавшемся обновлении или смене сеанса Discord операция откладывается. Исправную установку не переустанавливает. Другие модификации автоматически не заменяет. Настройки, аккаунты, группы и переключатель включения плагина не изменяет; существующий файл плагина не понижает до старой версии. Перед намеренным удалением плагина отключите задачу пунктом **4**.

Файлы задачи и журнал последней проверки: %LOCALAPPDATA%/RedflagAutoMute/maintenance. Архив установки после этого можно удалить. После несовместимого обновления Discord задача ждёт исправленного релиза BetterDiscord и применяет его автоматически с предупреждением о перезапуске. Пока разработчики не выпустили исправление, восстановить совместимость невозможно. Сбой самого плагина или его намеренное отключение не исправляются переустановкой BetterDiscord. Плагин автоматически обновляется из стабильных GitHub Releases раз в 6 часов. Проверяются источник, SHA-256 и версия; настройки сохраняются, Discord не перезапускается. При неудачном запуске включённого плагина выполняется откат. Пункт 6 отключает автообновление отдельно от восстановления. Для старых установок нужно один раз запустить новый ZIP и выбрать пункт 1. Скрипты фоновой задачи обновляются установщиком, а не автоматически.

### Установка вручную / macOS и Linux

Установите [BetterDiscord](https://betterdiscord.app/), скачайте `RedflagAutoMute.plugin.js` из релиза и скопируйте через **Плагины → Open Plugins Folder**. Включите плагин и вставьте приглашение. Автоматический установщик и проверка в живом Discord выполнены на Windows; другие платформы отдельно не проверялись.

## Пригласить друзей

**В вашу группу:** Мои группы → Открыть → Пригласить друга. Этот код `rfam1.…` одновременно настраивает Firebase и даёт членство в группе после входа. Передавайте его лично: получатель сможет читать группу и выдавать свои флажки.

**Только к вашей базе:** Подключение → Поделиться подключением. Код `rfdb1.…` содержит адрес Firebase и публичный ключ проекта. Друг подключится к той же базе и сможет создать свои группы, но **не увидит ваши закрытые группы** без отдельного приглашения.

Оба кода вставляются в одно поле «У меня есть приглашение». В них нет вашего пароля или токена входа. Приглашение к базе не даёт доступ к Google-аккаунту или Firebase Console.

![Подключение к базе и приглашение](docs/images/connection.png)

*Реальный интерфейс компонента плагина в демонстрационном окружении; все данные вымышлены. Оформление кнопок в Discord наследует его тему.*

## Флажки и группы

- **Один красный флажок** — мут. **Два жёлтых от разных участников одной группы** — тоже мут. Один жёлтый — предупреждение.
- ПКМ по человеку → **Redflag → ваша группа → флажок**. Отозвать можно свою карточку. Есть личное «всегда разрешать».
- Группа — независимый список внутри одной базы. Применяются только ваши **включённые** группы. Жёлтые из разных групп не складываются.
- Группу можно выключить для себя или покинуть. Владелец может удалить её для всех — с подтверждением.
- Красная рамка показывает статус в базе. Заметка содержит ID записи и время блокировки; исходный текст заметки сохраняется.

![Список групп](docs/images/groups.png)

## Перенести старые мьюты

Откройте группу → **Импорт / экспорт**:

1. **Выгрузить мои мьюты Discord** — получает сохранённые мьюты текущего клиента со всех серверов. По желанию включите громкость 0% и заблокированные аккаунты.
2. **Сохранить JSON-файл** — передайте его другу или сохраните резервную копию. **Выгрузить баны группы** сохраняет уже объединённый список группы.
3. Выберите JSON/TXT или вставьте ID → **Проверить список** → **Подтвердить импорт красных флажков**.

Импорт объединяется автоматически: ваш список `A, B` и список друга `B, C` дают **A, B, C**. Карточки обоих авторов сохраняются, повторный импорт не плодит записи и не меняет дату существующей красной карточки. Импорт выдаёт ваши красные флажки, действующие у участников выбранной группы; дата новых карточек — время импорта.

Discord ограничивает сохранённые индивидуальные аудионастройки: в проверенной сборке — 300 записей с вытеснением старых. Поэтому плагин держит полный список в Firebase, а звук и видео отключает только у участников вашего текущего звонка. Вход и сброс мута проверяются по событиям; резервная проверка — каждую секунду, изменения базы приходят по постоянному соединению Firebase (SSE). При сбое событийного соединения включается резервный опрос раз в 5 секунд; при сетевых ошибках — повтор через 30 секунд. Уже потерянную историю Discord восстановить из пустого места нельзя.

## Если вы первый в компании

Один человек один раз создаёт бесплатный Firebase-проект, включает Email/Password и Realtime Database и публикует [правила доступа](firebase/database.rules.json). Затем в плагине: **Подключение → Настроить свою базу**. [Пошаговая настройка Firebase](docs/REFERENCE.md#firebase-один-раз-для-всей-компании).

Регистрация в плагине создаёт **аккаунт внутри выбранного проекта**, а не новую базу Firebase. Другие участники используют ваше приглашение.

## Ограничения и приватность

- До **5 собственных групп на Firebase-аккаунт**, до **5000 пользователей с карточками в группе**, включая жёлтые. Лимиты проверяет сама база. Один человек с несколькими аккаунтами может обойти лимит числа групп.
- В публичной сборке нет личной конфигурации базы, паролей, приглашений, Discord ID или токенов владельца проекта. Публичный Firebase API key передаётся только внутри приглашения; доступ к данным определяется авторизацией и правилами.
- Не публикуйте `RedflagAutoMute.config.json`: там хранится ваша сессия и кэш. Установщик не запрашивает пароли и не меняет этот файл.
- Участники группы видят Discord ID и карточки друг друга. Плагин не запрашивает Discord token; запись личных заметок использует клиентский модуль Discord.
- При ошибке сети работает последний кэш. При отключении плагина снимаются только его мьюты; ручные сохраняются. Заметки при выключенном плагине содержат последний известный статус.

## Разработка

Node.js 22+; для плагина и сборки npm-зависимости не нужны.

```sh
npm run check          # тесты и сборка
npm run audit:release  # проверка личных данных и ключей
npm run package        # ZIP для Windows, контрольная сумма
```

Исходники: `src/`. Готовый плагин: `dist/RedflagAutoMute.plugin.js`. [Архитектура, правила доступа и ручные проверки](docs/REFERENCE.md).

Репозиторий сохранил прежнее имя `Vencord_RedflagAutoMute`, но версия **2.0.3 работает на BetterDiscord**. Прежний прототип доступен в истории Git.

История выпусков: [CHANGELOG.md](CHANGELOG.md).

Журнал доставки плагина: `%LOCALAPPDATA%/RedflagAutoMute/maintenance/plugin-update/state.json`. При сетевой ошибке установленная версия продолжает работать; следующая проверка — через 6 часов.
